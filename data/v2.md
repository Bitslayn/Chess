# Chess compression v2

## Placement Operators (Huffman tree)
The operator tells the parser what to do with the next several bytes. It is impossible to start with a repeat operator. Pairing an operator with its defining bits forms a single instruction.
```
b0 - Piece
b10 - Next
b11 - Repeat
```

### Piece - 4 (+1) bits
Immediately following the `piece` operator, defines the piece at the position. The first bit is the color and the last 3 bits are for the piece itself. En passant and castling are also represented here.
```
b0 - White
b1 - Black

bX000 - Pawn
bX001 - Bishop
bX010 - Knight
bX011 - Rook
bX100 - Queen
bX101 - King
bX110 - Pawn (En passant)
bX111 - Rook (Castle-able)
```

### Next - 1 (+2) bits
Immediately following the `next` operator, a bit defines whether to increment the row or the column by 1. These start at rank 1, column 1 and moving to the next row resets the column back to 1.
```
b0 - Row (Rank)
b1 - Column
```

### Repeat - 3 (+2) bits
Immediately following the `repeat` operator, defines how many times to repeat the last instruction using the binary representation of a 3-bit number or 1-7 additional times.

## Additional Information
Bits are read as additional information when the row exceeds 8.

### Turn Side - 1 bit
Flag that shows whose turn it is
```
b0 - White
b1 - Black
```

### Halfmove Clock - 6 bits
Keeps track of the fifty-move rule using a 6-bit number or 0-50

### Fullmove Clock - 8 bits
Keeps track of the number of full moves using an 8-bit number or 1-256. Even though there is no limit to the number of moves, this number is limited as it is improbable to have this many moves happen in a game.
